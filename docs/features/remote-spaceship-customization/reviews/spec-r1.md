# Spec Review — r1

## Verdict rationale

The direction is sound and the core design is feasible: the catalog arithmetic checks out (1,351 rows; 123/121 per slot; 1,340 lootable; 11 standard; 670/670; 2,680 weight; 75/25; `rng 0 → hull-obsidian`; `rng 0.999999/1 → shot-kite-solar`), the v2 rows are preserved, the camera-geometry basis for spectated-only ships holds for the supported aspects, and guest/account authority is explicitly reasoned (Q-4). However, the spec is **not buildable as written**: two pinned acceptance numbers are internally contradictory or factually wrong (AC-30's `Shots` all-owned count; AC-22's 173-object budget built on a non-existent 136-object baseline), a required `MemberState.appearance` field breaks unowned frontend fixtures (guaranteed mid-build typecheck dead end), and the `coin-economy` sequencing gate omits the very file its open fix-up round is editing (`engine.test.ts`, T8 is `[P]`). Six further MAJOR gaps (AC-14's undefined 24-member welcome fixture; no path for a live `memberAppearance` update of the mounted remote ship; the unowned `SpaceshipPreview`/`preview` files still on the v2 mapping; stale README/glossary/observability docs; guest-rejoin self-view convergence; panel v3 normalizer switch unstated) would each produce wrong work or fail acceptance.
