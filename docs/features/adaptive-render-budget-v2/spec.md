# Spec — Adaptive Render Budget v2

## Summary

CubeClicker renders the full Three.js scene — `EffectComposer` with SSAO + bloom, a 2048² soft-shadow map, and a capped device pixel ratio — from the moment the app mounts, behind an auth menu that the player may stare at for many seconds, and it computes a 120-sample p95 by copying and sorting the window on **every** frame. This feature makes the client spend GPU time only when the game is actually being played and makes the already-existing automatic high/medium/low tier control GPU cost, not just CPU-side particle/mesh counts: the renderer, scene, and `requestAnimationFrame` loop are created only after the auth gate closes; high keeps today's exact look (SSAO + bloom + 2048 shadows + DPR cap 2), medium keeps bloom with a 1024 shadow map and a lower DPR cap, and low uses the plain renderer with no SSAO/bloom, no shadows, and DPR cap 1. The p95 percentile is maintained in a sorted window so no frame sorts 120 values. Raw request: find performance optimizations and "Proceed with all of them, one by one"; this is the first performance item of the approved audit queue (`P-01`, `P-02`, `P-03`, `P-09`).

## User stories

- As a player on a phone or an older laptop, I want the game to stop spending GPU time while I am still choosing how to enter, and to drop expensive effects when frames miss budget, so the click loop stays responsive.
- As a player on capable hardware, I want the current visual quality — soft shadows, ambient occlusion, bloom — to look exactly as it does today.
- As a player with reduced motion enabled, I want the GPU tier to change only static cost (resolution, shadows, post-processing), never to re-enable or disable motion.
- As a maintainer, I want the existing automatic tier policy, thresholds, cooldowns, and CPU feature matrix to stay untouched so accepted behavior does not drift.
- As a reviewer, I want every tier decision, adapter transition, and gate-attach path pinned by a concrete test with expected values.

## Acceptance criteria

### Deferred attach (P-01)

- **AC-1 — Gate-gated attach, guest.** While the auth gate is open (`gateState.view === 'menu'`), `App` renders the canvas element but does not call `session.attach`, does not invoke the renderer factory, and schedules no frame. Selecting `Play as guest` closes the gate and produces exactly one `session.attach` call with the canvas element, after `session.join('guest')`. Evidence: `App.test.tsx` (jsdom, attach spy) and `GameCanvas.test.tsx`.
- **AC-2 — Gate-gated attach, login, and no missed welcome.** A verified login closes the gate and produces exactly one `session.attach`, after `session.retryConnection()` and `session.join('account')` (the existing invocation order is preserved). While detached, `session.retryConnection()` does not call `transport.connect()` or `transport.close()`; it only sets `status = 'connecting'` and `welcomed = false`. The attach-time `transport.connect()` is called exactly once; because no socket exists before the gate closes, the WebSocket upgrade happens after the login and therefore carries whatever session cookie is current — the cookie-at-upgrade rule is unchanged and is evidenced by the existing `ws/connection` tests plus the manual containerized step in `plan.md` § Verification step 2 (the named session test observes the connect count, not the cookie). The detached-retry path must not miss a welcome: `session.test.ts` contains the test `'receives welcome after a detached retryConnection → join(account) → attach cycle'`, which records `transport.onMessage` and `transport.onStatus` before `transport.connect`, runs `retryConnection()` → `join('account')` → `attach(canvas)`, emits a valid `welcome`, and asserts (a) `messageHandlerCount() > 0` and `connectCount() === 1` with `closeCount() === 0` for the detached phase, (b) `getMultiplayerSnapshot().world.serverId` equals the welcome's server id, and (c) the next scheduled frame advances the intro (welcomed releases `canRun`). Evidence: that test plus `App.test.tsx` (attach/retry/join call order); cookie evidence: `plan.md` § Verification step 2 and the unchanged `ws/connection` path.
- **AC-3 — Gate-gated attach, registration and pending verification.** Registering shows the verification-pending screen with the gate still open: attach count stays `0`, and no renderer factory call or scheduled frame occurs. `Back to login` also keeps the gate open and attach at `0`. Only a verified login or `Play as guest` closes it. Evidence: `App.test.tsx` (jsdom).
- **AC-4 — Gate-gated attach, initially closed, and gate close/reopen.** The App props are `chosen` / `guest`; `App` computes the gate option `initiallyClosed: initialChosen(rest)`. With `chosen: true` (or `guest: true`), the gate starts closed and the session attaches exactly once on mount without any menu interaction. The SSR canvas markup remains byte-identical to today: `<canvas tabindex="0" aria-label="Game canvas: click a mini-cube to explode it; press W, A, S, D or the arrow keys to rotate the cube" style="touch-action:none"></canvas>`. The effect is defined for `active: true → false → true`: going inactive disposes exactly once; going active again attaches exactly once and schedules exactly one frame with a fresh adapter/scene. This sequence is not reachable from the gate today (logout clears the auth store but does not reopen the gate), so the test drives `GameCanvas` directly and also simulates a StrictMode-like mount → unmount → remount. Counts are stated unambiguously: first attach = `1`, dispose = `1`, second attach = `2`; final attach count `2`, final dispose count `1`. Evidence: `GameCanvas.test.tsx`, `App.test.tsx`.

### Quality tiers control GPU cost (P-02, P-03)

- **AC-5 — Pinned GPU budget matrix.** `qualityFeatures(tier, reducedMotion)` exposes four new fields with these exact values, independent of `reducedMotion`:
  | Tier | `ssao` | `bloom` | `shadowMapSize` | `pixelRatioCap` |
  | --- | --- | --- | --- | --- |
  | high | `true` | `true` | `2048` | `2` |
  | medium | `false` | `true` | `1024` | `1.5` |
  | low | `false` | `false` | `0` | `1` |
  `QUALITY_SHADOW_MAP_SIZES` equals `{ high: 2048, medium: 1024, low: 0 }`; `QUALITY_PIXEL_RATIO_CAPS` equals `{ high: 2, medium: 1.5, low: 1 }`; the high shadow size equals the existing exported `KEY_SHADOW_MAP_SIZE = 2048`; the high DPR cap equals the existing `PIXEL_RATIO_CAP = 2` in `game/effects.ts`. The existing CPU fields (`cursorMeshCount` 21/17/15, `impactShards` 14/7/0, `sparks` 24/12/0, `explosionFlash` 1/1/0, `explosionEmbers` 8/4/0, `explosionSmoke` 4/2/0, `shotFx` true/true/false) are unchanged. Evidence: `quality.test.ts` exact-object assertions and constant pins.
- **AC-6 — High tier is visually identical to today.** For high, `createPostprocessing(renderer, scene, camera, 'high')` builds exactly `[RenderPass, SSAOPass, UnrealBloomPass, OutputPass]` with the pinned SSAO (`0.5 / 0.005 / 0.1`) and bloom (`0.45 / 0.4 / 0.85`) parameters; `renderer.shadowMap.enabled` is `true`; `keyLight.castShadow` is `true` and its `shadow.mapSize` is `2048 × 2048`; the effective DPR is `min(devicePixelRatio, 2)`; the adapter renders through the composer. Evidence: `postprocessing.test.ts`, `webgl.test.ts`, `scene.test.ts`.
- **AC-7 — Medium tier.** For medium the composer is exactly `[RenderPass, UnrealBloomPass, OutputPass]` (no `SSAOPass` constructed), shadows stay enabled with a `1024 × 1024` key-light map, and the effective DPR is `min(devicePixelRatio, 1.5)`. Evidence: the same three test files forced to medium.
- **AC-8 — Low tier.** For low the adapter never constructs an `EffectComposer`: each `render(scene, camera)` is exactly one `renderer.render(scene, camera)` call; `renderer.shadowMap.enabled` is `false`; `keyLight.castShadow` is `false` (no shadow map is rendered; the existing 2048/1024 map is not resampled); the effective DPR is `min(devicePixelRatio, 1)`. Evidence: `webgl.test.ts`, `postprocessing.test.ts` (never called at low), `scene.test.ts`.
- **AC-9 — Runtime tier transitions.** Forcing `low → medium → high → medium → low` through the existing `setQualityTierForTesting` hook: every replaced composer is disposed exactly once; the next `render` builds the pass list for the new tier; the last `setSize`/`setPixelRatio` values are replayed onto the rebuilt composer exactly once (last value wins); returning to high restores SSAO + bloom + a 2048 shadow map; no frame performs more than one composer/base render; `render` after `dispose` remains a no-op and constructs nothing. Evidence: `webgl.test.ts`, `postprocessing.test.ts`, `scene.test.ts`.
- **AC-10 — Session propagation and DPR.** On the first attach the session calls `adapter.setQuality(view.getQualityTier())` before the first `adapter.setSize`. On any frame where `view.getQualityTier()` changed, the session calls `adapter.setQuality(newTier)` exactly once, before that frame's `adapter.render`, and re-applies `setPixelRatio(min(devicePixelRatio(), QUALITY_PIXEL_RATIO_CAPS[tier]))` in that same frame. Frames whose tier is unchanged add no `setQuality` calls. Evidence: `session.test.ts` recording fake adapter and call-order assertions, plus the production-adapter contract test in `webgl.test.ts` that drives `createRealisticRenderer` through the same sequence (medium → pixel ratio/size → render → low → render → idempotent low → high → render).

### P95 cost (P-09)

- **AC-11 — Exact nearest-rank p95 without per-frame sort.** The policy maintains the live window plus a sorted view of it (binary insertion on push, removal of the evicted oldest value). After every push, `getP95FrameMs()` equals the nearest-rank value `sorted[ceil(0.95 * n) - 1]` of the live window computed by a naive reference implementation, including during eviction past 120 samples and with duplicate values. Running 10,000 pushes with a temporary `Array.prototype.sort` that throws completes without invoking `sort`, and the final tier and p95 are exact. All pre-existing policy tests (thresholds, boundary values, hysteresis, cooldowns, one-tier-per-decision, clamping, min samples, recovery) pass unchanged; the 60-frame decision timing is preserved (a constant 30 ms stream still downgrades on its 60th frame). Evidence: `quality.test.ts`.
- **AC-12 — p95 exactness across the rolling window (pinned stream).** The stream is exactly 60 pushes of `30`, then 60 pushes of `10`, then 60 pushes of `10` (180 pushes total). Expected values after each block:
  | Block | Pushes | `getWindowSize()` | `getAverageFrameMs()` | `getP95FrameMs()` | Tier after block |
  | --- | --- | --- | --- | --- | --- |
  | 1 | 60 × `30` | 60 | 30 | 30 | `medium` |
  | 2 | 60 × `10` | 120 | 20 | 30 | `medium` |
  | 3 | 60 × `10` | 120 | 10 | 10 | `low` |

  The complete tier sequence is `high` after pushes 1–59, `medium` after pushes 60–159, and `low` after pushes 160–180. The high→medium downgrade fires on push 60 (60-sample gate + 60-frame streak). The medium→low downgrade fires on push 160: its miss streak reaches 100 against the 60-frame gate and its cooldown reaches exactly `1000 ms` on that push, while push 159 is still blocked at `990 ms`. No upgrade fires within the 180-push stream: the low→medium gate requires 240 stable frames, and the stream ends before that gate can be reached. The test asserts only observable values (`getWindowSize`, `getAverageFrameMs`, `getP95FrameMs`, and the tier); the internal stable-streak counter is not part of `QualityPolicy` and is not asserted. Evidence: `quality.test.ts`.

### Lifecycle correctness (P-01, P-02)

- **AC-13 — Late-create, pause, resize, dispose, re-attach, context loss.** With attach deferred: (a) no resize/visibility/pointer listener and no frame exists before the gate closes (listener counts `0`, in `GameCanvas.test.tsx`/`App.test.tsx` and the session fake's listener/scheduler counts); (b) a resize emitted while detached neither throws nor creates a renderer; (c) the attach-time viewport apply sizes the renderer from the current `getBoundingClientRect()` and caps DPR by the current tier; (d) attaching while the tab is hidden creates the renderer but schedules no frame, and becoming visible schedules exactly one, with no time jump (the baseline is reset); (e) `dispose()` before the first render disposes the adapter exactly once and constructs no composer; (f) `dispose()` then `attach()` creates a fresh adapter and scene pair and exactly one scheduled frame; a callback that escapes `cancel` after dispose performs no render; (g) a synthetic `webglcontextlost` followed by `webglcontextrestored` dispatched on the canvas during the intro does not throw, does not change the scheduled-frame count, and adds no `webglcontextlost`/`webglcontextrestored` listener of our own (the session's canvas listeners remain exactly the five pointer handlers). No restore handler is added; three.js's built-in restore path remains the only one, and the adapter holds no GL state outside the renderer/composer it disposes. Evidence: `session.test.ts`, `webgl.test.ts`, `GameCanvas.test.tsx`, `App.test.tsx`.
- **AC-14 — Reconnect behavior unchanged once running, and the detached path receives the welcome.** With the session attached, a transport `disconnected` status and the banner `Retry` still run `transport.close()` + `transport.connect()` exactly once and produce exactly one `connecting` publish; `join(mode)` before attach is retained by the transport and sent on `hello` (existing `lastMode` behavior). The detached login path is covered by AC-2's `'receives welcome after a detached retryConnection → join(account) → attach cycle'` test; a missed welcome (subscribe-after-connect, or a retry that opens a socket before attach) fails that test. No protocol message, server rule, or reconnect contract changes. Evidence: `session.test.ts` (that test plus the existing detached cases) and `transport.test.ts` (unchanged, re-run).

## Security considerations

- **No user-controlled data reaches the renderer.** Tier and budget values are code constants; the tier is derived from frame times only. There is no input parsing, storage, URL parameter, or persistence surface added.
- **No secrets and no dependency change.** The feature edits existing frontend modules only; no package, lockfile, env, or bundle secret is touched. `npm ls`/bundle content is unchanged.
- **Auth is not weakened by deferring attach.** The server still resolves the account from the session cookie at the WebSocket upgrade and remains the authority for `join`; the client-side gate is presentation. A guest can still join; an unverified account is still rejected server-side. The deferred `retryConnection` only avoids opening a socket before the session can subscribe; it does not bypass any check.
- **Resource discipline.** Disposing replaced composers and not constructing them at low prevents GPU/memory growth across tier oscillations; `dispose()` remains idempotent and render-after-dispose is a no-op, so a stray callback cannot render a released context.
- **Persistence integrity.** No persistence is added or read.

## Real-time / multi-client

Explicitly **client-local rendering only**. No shared or cross-client state is created, read, or displayed differently; no protocol message, server rule, identity rule, reconnection contract, or server-authoritative value changes. The first connection opening later is a client lifecycle detail: once attached, connect/reconnect/grace/resume behavior is byte-for-byte the existing path (`transport.ts` unchanged). Guest/account identity and "no account required" are unaffected; no identity conflict is introduced.

## Open questions

**Approval checkpoint.** The `awaiting_approval` summary must present, explicitly and not generically: (a) the `user-authentication` AC-18 animation-clause supersession with the intro-from-start-at-gate-close default (Q-2); (b) Q-1's low-tier shadows-off default; and (c) Q-3's `2 / 1.5 / 1.0` DPR ladder. The user's blanket "Proceed with all of them, one by one" does not by itself approve a pinned visual clause change; approval must name AC-18's intro behavior before building starts.

- **Q-1 — Low-tier shadows.** Recommended default: shadows fully off at low (`renderer.shadowMap.enabled = false`, `keyLight.castShadow = false`), because a static/baked shadow adds a mesh, a material, and a second visual definition to maintain for a tier already at DPR 1 with no post-processing. Alternative: one cheap static contact-shadow plane. Planner default is "off"; the user may choose the static variant without changing any other tier.
- **Q-2 — Intro timing after the gate closes.** Recommended default: the intro plays from its start when the gate closes (the menu previously consumed the cinematic; only rendering was deferred, not engine semantics). Alternative: skip the intro on late attach and begin in `playing`. The recommended default keeps `engine` behavior untouched and reuses the existing skip input (any key / tap) so players can bypass the 2.5 s.
- **Q-3 — DPR ladder.** Recommended default: `2 / 1.5 / 1.0` (high/medium/low). Alternatives: medium `1.25`, low `0.75`. These are single-constant edits in `quality.ts` if the containerized visual pass shows low is too soft; the AC-5 table would be revised in a follow-up revision.

## Assumptions

- **A-1** — The auth gate is terminal once closed (`closed` never returns to `menu`); `AuthStore.logout` clears session state but is not wired to reopen the gate. The only detach is React unmount, a gate close/reopen driven directly in tests, or StrictMode's development double-effect; the idempotent attach/dispose contract handles all three (AC-4 pins the `true → false → true` and remount sequences).
- **A-2** — `gateState.view` is the single gate signal; no URL/route or persisted choice reopens the game without a choice.
- **A-3** — Keeping the `<canvas>` mounted (without attaching) preserves the SSR markup pins and the overlay's layout; the page background (`#000000`) is what shows behind the menu while deferred. This visual consequence is accepted with AC-18's animation clause supersession.
- **A-4** — `three@0.186.1` reallocates a light's shadow map only after `shadow.map.dispose()` and `shadow.map = null`; setting `mapSize` alone is a no-op for an existing map.
- **A-5** — `EffectComposer.dispose()` releases its render targets in the pinned three version, so disposing and rebuilding per tier change does not leak.
- **A-6** — The existing `setQualityTierForTesting` hook remains the only forced-tier seam; production has no override, so the manual pass relies on real frame times (CPU throttling) plus visual differences and the canvas backing-store size.
- **A-7** — `retryConnection()` before attach is only reachable through the auth gate's login path; no other caller exists. Its detached behavior change therefore does not affect any other surface.
- **A-8** — The frontend test environment supports `@vitest-environment jsdom` (already used by `App.test.tsx`), so `GameCanvas` attach gating is testable without a new test environment dependency.
