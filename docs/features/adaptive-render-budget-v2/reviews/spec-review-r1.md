# Spec Review — r1

## Summary
❌ changes requested — 1 BLOCKER, 2 MAJOR, 10 MINOR, 4 INFO. The direction is sound and the source claims are mostly accurate: `session.attach` already subscribes `transport.onMessage`/`onStatus` before `transport.connect` (`session.ts:1315-1319`), the auth gate's methods match the AC-1..4 order (`App.tsx:276-289`), `GameCanvas` has the pinned SSR markup, `quality.ts` still sorts a copy of the window every frame (`quality.ts:227-232`), and `createPostprocessing` is a 3-argument export (`postprocessing.ts:75-80`). The tier matrix, high-tier parity, p95 design, and supersession ledger are largely well specified.

The blocking problems are: (1) the task graph marks T3 `[P]` and says "T3 ∥ T2" while T2 is `[seq]`, so the orchestrator's all-`[P]` parallel rule can never execute that pair; the full-frontend-suite verify is also shared between T2/T3/T4 and unreliable in an interleaved build; (2) AC-2/AC-14 do not pin the `welcome`-after-detached-login path, and the user explicitly requires that the auth-gate flow cannot miss a welcome; (3) AC-12 is not binary-testable as written ("e.g." stream and `['high','medium',...]` ellipsis), and the example stream does not reach the claimed medium transition. The ledger also omits the `createPostprocessing` signature change and blurs the `createWebGLRenderer`/`createRealisticRenderer` low-tier distinction.
