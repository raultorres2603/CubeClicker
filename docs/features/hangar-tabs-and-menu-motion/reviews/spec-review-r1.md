# Spec Review — r1 (hangar-tabs-and-menu-motion)

## Summary

❌ **Changes requested — 4 BLOCKER, 4 MAJOR, 8 MINOR/INFO.** The direction is sound: the five two-slot groups match the real 10-slot catalog, the `tablist`/`tab`/`tabpanel` structure, roving tabindex plus Arrow/Home/End, one preview outside the keyed subtree, the `owned/4` badges, the 44 px/5.5 rem geometry, the sticky single-scroll container and the CSS-only open-only menu boot are the right shape and testable in the project's SSR/jsdom/CSS-guard style. Approval is blocked by four acceptance criteria that cannot pass as written (F1–F4) and four MAJOR defects that will produce wrong work (F5–F8): three wrong concrete values (`AC-1` slot concatenation, `AC-5` legacy badge count, `AC-10` control count), a keyframe contradiction (`AC-12` bans `height` while `menu-rail` animates it), a reduced-motion cascade that leaves the hangar boot running under `prefers-reduced-motion` (`AC-17`), dangling `aria-controls` (`AC-2`), two unpinned keyframe percentage sets (`AC-12`), and a stale base where `T5`/`AC-17` re-add `data-reduced-motion` that the in-flight game-feel-overhaul review fixes already put on `<main>`.

Count convention: `blocking` counts BLOCKER-severity findings; `nonblocking` counts MAJOR + MINOR + INFO. The four MAJORs (F5–F8) are still gate-failing under the review skill's rule (any open BLOCKER or MAJOR → `changes_requested`) and must be fixed in the same revision.
