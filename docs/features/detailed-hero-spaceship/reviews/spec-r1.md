# Spec Review — r1

## Summary

❌ changes requested — the package is detailed, feasible, and well-scoped: 48 procedural meshes/11 shared materials/≤6,000 triangles, a new testable `spaceship-model.ts`, a disjoint T1→T2→T3 split, the T16 camera-anchored composition preserved by the untouched outer `hero-ship` group, and explicit predecessor supersessions. One arithmetic error blocks approval: AC-12/plan/T2 call the non-hero disposal set “22 meshes”, but the existing 22 backdrop meshes include the 7 hero meshes; after this change the non-hero set is 15, the hero set is 48, and the total is 63. Several MINOR testability/guard gaps should be fixed in the same revision.

## Notes / backlog (non-blocking)

- **Feasibility:** the plan is implementable with the accepted `three@0.186.1` (`CylinderGeometry`, `ConeGeometry`, `BoxGeometry`, `SphereGeometry`, `TorusGeometry`, `ExtrudeGeometry`, `Shape`, `MeshPhysicalMaterial`, `MeshBasicMaterial`, `AdditiveBlending`, `Box3`, `Group`, `Mesh`); no new dependency or asset is needed. The 48-mesh/11-material split, 63-mesh backdrop, 70-object backdrop and 102-object scene are coherent once F1’s non-hero count is corrected to 15.
- **Composition arithmetic:** the 1.7 inner scale projects the 4.6-local ship to ≈225 px at 1280×720 and ≈400 px at 2560×1280, inside AC-16’s 160–280/320–560 ranges; the pre-feature T16b evidence (hero hull at y≈303–310 px vs panel top ≈360–362.5 px at 1280×720) leaves enough vertical room for the new hull height at the existing ±0.25 bob, but the AC-16 screenshot check remains the authority.
- **Fidelity judgment (written description):** the plan covers every written element; the weakest approximations are “rivets” (represented by greebles/seams, documented) and “layered armor plates” (one belly plate + spine + seams, F20). Both are acknowledged as procedural limits, and Q-1 is the user’s fidelity checkpoint.
- **Open questions:** Q-1 (procedural vs asset) and Q-2 (hero ship vs cursor) are genuine approval-time user decisions; Q-3/Q-4/Q-5 are visual defaults that are safe to approve with the pinned values; Q-6/Q-7 are risk/scope defaults; Q-8 is future work (F19).
- **Backlog candidates:** the F2/F8/F9/F10/F11/F12 testability wording, F4 protected-path expansion, F5 wing margin, F6/F7 documentation alignment, F13 stale `scene.ts` comment, F14 unused-import note, and F15–F20 metadata/risk notes. None of these change the feature’s scope or the verdict beyond F1.
