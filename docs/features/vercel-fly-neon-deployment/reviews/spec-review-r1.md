# Spec Review — r1

## Summary

❌ changes requested — 4 BLOCKER, 1 MAJOR, 4 MINOR, 1 INFO. The architecture is correct: Vercel is explicitly frontend-only, Fly runs the persistent single-process Fastify/WebSocket backend, Neon holds the durable account/economy data, and the plan does not assume Vercel can host the WS service. The blockers are execution-level: T1–T4 are declared parallel-safe but share root lint/typecheck and the backend test suite; AC-23's connection-string audit already matches the repository's fake test fixtures; AC-4's "no `ws://localhost:8080/ws` in the cloud bundle" proof contradicts the planned local-fallback literal; and the migration path runs the startup migration through the pooled `DATABASE_URL` and uses `BEGIN`/`COMMIT` on a `pg.Pool` without a pinned connection. The Vercel CLI working directory is also unpinned.

## Notes / backlog (non-blocking)

- **Q-5/Q-14 remain user-owned:** archive vs delete for `infra/terraform/**` and the live development assets are explicit decisions; the spec correctly says the feature is `blocked` rather than accepted without AC-19. The orchestrator must not start T7 or claim AC-19 until they are confirmed.
- **F6–F9 are minor clarifications** (optional `VITE_WS_URL`, dev SMTP vs Mailpit, Fly region source, trailing-slash normalization); they do not change the platform architecture but should be fixed in the same revision because the builder will otherwise have to choose.
- **F10 is a contingency:** the primary Vercel Root Directory/CLI path should be proven first; only define the root `vercel.json` fallback if that build fails.
- **Vercel cannot host the WS backend** is correctly stated (D-1/architecture): Vercel serves the static SPA, Fly runs the persistent process, Neon is the database. The local `podman compose up` path and the nginx prod image remain intact.
- **Cross-site auth risk is not silently ignored:** the spec flags Safari/iOS ITP and third-party cookie blocking and recommends first-party subdomains with `SameSite=Lax`; development default hosts use `None; Secure` for Chrome-based testing, and Q-2/Q-13 record the decision.
