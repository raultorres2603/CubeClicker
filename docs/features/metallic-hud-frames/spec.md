# Spec — Metallic HUD Frames

## Summary

A frontend-only restyle that replaces the current glassy/neon HUD chrome with a **metallic blue-gray frame** carried by a brushed-metal gradient band, a **cyan glow** around the silhouette, **angled/beveled corners**, and **dark translucent centers**, applied uniformly to every menu and box in the shell: the game statistics HUD, the "Users on Server" boxes and controls, the connection banner, the phase announcement, the auth menu/form/verification card, its buttons, its form fields (`.auth-input` and the verification-pending input) and its inline error box. The raw request is: *"I want this type of HUD, not the one you created. Change all menus and boxes to be this type: [Image 1]"*; the image was not viewable by tooling and the user confirmed the generic description **"Metallic blue-gray frames with cyan glow"** and chose a new feature over revising `futuristic-hud-blue`. The change is CSS-only inside `src/frontend/src/ui/app.css`: no React markup, state, networking, backend, or container change. Because the new bevels cannot be followed by the previous rectangular "border light" ring, that ring is retired and replaced by a masked frame sheen — a 2px highlight travelling along the inner edge of the metal band, positioned at the padding-box edge so the HUD's retained `overflow: hidden` cannot clip it; this supersession is enumerated below and the predecessor specs remain unedited. Game rules, server authority, persistence, and cross-client state are untouched; all visuals stay local to one client.

## User stories

- As a player, every menu and box I see shares one metallic blue-gray frame with a cyan glow, so the interface matches the HUD reference instead of the old rounded glass panels.
- As a player, the panels have angled/beveled corners and dark translucent centers, so they read as armored HUD chrome while text stays legible over the scene.
- As a player, the primary actions, fields and the high-frequency HUD stay usable: hover, focus and disabled states are still visible on the new frames.
- As a player who prefers reduced motion, the animated frame sheen (like the retained scanline and blink) is disabled.
- As a maintainer, the restyle touches only the stylesheet and its source guards, so markup contracts, component tests, game logic, protocol, and container assets stay stable.

## Security considerations

- **No new dependencies.** CSS and test-source edits only; lockfile untouched.

## Open questions

- **Q-1 — Reference image / exact geometry (user checkpoint).** The supplied image could not be viewed by tooling; the user confirmed only "Metallic blue-gray frames with cyan glow". Default: brushed blue-gray metal band (2px), 8-point cut corners at `0.75rem` (HUD, users box, error), `1rem` (auth card), `0.5rem` (banners), cyan outer glow, near-black translucent centers. If the reference has a different cut pattern (e.g. only two opposite corners clipped), a wider band, rivets/notches, or different proportions, this needs a CSS revision (constants + guards).
- **Q-2 — Scope of "all menus and boxes".** Default framed surfaces: `main > section`, `.user-panel section`, `.connection-banner`, `.phase-announcement`, `.auth-panel`, `.auth-error`; framed controls: the users toggle/return, Retry, auth and verification-pending buttons; inset wells: `.auth-input` and `.verification-pending input` (the auth form fields and the verification-pending email field). Member list rows, the HUD minimize glyph button, and the `/?token=` verification route are not framed: rows and the glyph are items inside framed boxes, and `.verify-email` is a status page today, so framing it would add a card layout to a surface the request does not call a box — a scope/design decision (not a markup limitation), deferred.
- **Q-3 — Retiring the animated border light.** Default: replace the conic border-light ring with a masked sheen travelling as a 2px highlight along the inner edge of the metal band (AC-9), because a rectangular ring cannot follow the eight-point bevel and duplicates the metal edge. Alternative: no animated chrome at all (static metal + glow) — a constant edit plus a spec note.
- **Q-4 — Connection banner semantics.** Default: the amber warning border is replaced by the unified metal/cyan frame; the state is carried by the existing text ("Connection lost", "retrying…") and the Retry button. Alternative: keep an amber glow only for `disconnected`/`exhausted` (a state selector and a second glow token).
- **Q-5 — Error box glow.** Default: `.auth-error` keeps a red-tinted center and a red glow (`--frame-glow-alert`) so error semantics survive the unified metal band; the default is now pinned by AC-21 and its contrast by AC-22. Alternative: cyan glow with red text only (would drop AC-21's token overrides).
- **Q-6 — Scanline retention.** Default: the existing `main > section::after` scanline is retained (clipped by the bevel). If it reads as noise on the metal, remove it — a constant edit plus a spec note.
- **Q-7 — Palette and bevel tuning.** The four metal hexes, the two glow alphas, and the three cut sizes are defaults; tuning is a token edit with the guards updated to the new pinned values.
- **Q-8 — `filter` performance.** Several `drop-shadow` filters and one animated sheen per framed surface are cheap on desktop; if low-end devices stutter, the sheen can be dropped (Q-3) and the glow reduced without layout changes.
- **Q-9 — Backdrop treatment.** Default: the full-viewport `.auth-menu`/`.auth-forms` scrim is not framed (it is not a box). If the reference shows a framed modal backdrop, that is a separate change.

## Assumptions

- All restyled surfaces already have stable selectors and appear in the rendered shell without new markup; the styled `<section>`s inside `<main>` are only the HUD/pre-welcome stats panel, so `main > section` remains unambiguous.
- `clip-path` clips an element's own focus `outline`; therefore framed controls use inset `box-shadow` rings (AC-8) while the existing outline declarations stay for non-clipped fallbacks.
- `filter: drop-shadow` is used for the cyan glow because `clip-path` clips the element's outer `box-shadow`.
- The sheen pseudo-element is absolutely positioned against its parent's padding box (`inset: 0`), so its masked 2px ring lies inside `main > section`'s `overflow: hidden` clip; a negative inset would be clipped away on the HUD (review F1).
- No framed surface contains `position: fixed` descendants, so `filter`'s containing-block side effect is harmless.
- Text colours and the composited center backdrop keep the existing WCAG AA gate; the new center composites to a dark surface with a contrast ratio of roughly 16.3:1 against `HUD_TEXT` (≥ AA and above the 12:1 gate of AC-17).
- The alert center composites to roughly 15.7:1 against `HUD_TEXT` and roughly 10.3:1 against `#ffb4b4`; the well is darker than the center; disabled text at `0.62` alpha composites to roughly 6.8:1 against the frame center. All clear their AC-22/AC-23 gates.
- Predecessor specs/plans/tasks stay authoritative for everything not superseded; this spec never edits them.
- Stack unchanged: TypeScript strict, Vitest, ESLint; the project testing bar governs.
