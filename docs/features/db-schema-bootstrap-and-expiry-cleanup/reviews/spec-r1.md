# Spec Review — r1

## Summary

❌ changes requested — 1 BLOCKER, 1 MAJOR, 6 MINOR, 6 INFO. The design direction is sound: the in-process bootstrap/cleanup split is justified against the raw request, the partial supersession of `vercel-fly-neon-deployment` AC-10 is accurately scoped and retains the important behavior, and D3/D4/D7 (create-missing/warn-drift, direct-URL advisory lock, recursive-timeout cleanup with stop-before-close) are defensible against Render/Neon constraints. Two binding gaps remain: the log contract requires `debug` events that the existing `LogSink` cannot emit while no task owns the shared logging contract or its test doubles, and the required schema contract's defaults/NOT NULL are underspecified while AC-1/AC-2 only compare table/column names, so a recreated `sessions`/`verification_tokens` table can pass every test and still fail runtime inserts. The rest are traceability/verification gaps, not redesigns.

## Notes / backlog (non-blocking)

- **F9 (INFO) — required-index drift is not detected on an existing table.** `spec.md:106-114` lists the two `users` functional unique indexes, but AC-6/D3 check only missing columns; a pre-existing `users` table missing `users_username_lower_uq`/`users_email_lower_uq` passes silently, leaving case-insensitive uniqueness unenforced. D3 and the non-goals deliberately exclude index repair, so this is not a scope violation; consider a warn-only index check or an explicit Security/non-goal sentence that missing indexes on existing tables are not detected.
- **F10 (INFO) — status/supersession bookkeeping.** `docs/features/db-schema-bootstrap-and-expiry-cleanup/status.md:15` still says the task board is "(empty until tasks.md exists)" while `tasks.md` exists (orchestrator-owned; update on transition). The predecessor `vercel-fly-neon-deployment` is `state: blocked` (`docs/features/vercel-fly-neon-deployment/status.md:3`) with T1–T6 done and T7 (live proof) blocked; the spec's supersession table is accurate about the shipped startup seam, but the orchestrator's "accepted" framing should note that the supersession is of the implemented AC-10 behavior, not of the whole predecessor feature.
- **F11 (INFO) — Render downtime wording.** `docs/architecture/vercel-render-neon.md:35` says Render uses zero-downtime deploys with an old/new overlap; `docs/architecture/deployment.md:95` says "there is no zero-downtime deploy, by design and by the room model". The advisory-lock design is safe under either behavior; the T9 docs pass should reconcile the two sentences (or the spec should phrase the D4 rationale as "if the provider overlaps old/new instances").
- **F12 (INFO) — pooled fallback caveat.** `plan.md:47` resolves `DIRECT_DATABASE_URL` over `DATABASE_URL`; on the current Neon env both are set (direct for migrations/startup, pooled for runtime). If a deployment sets only `DATABASE_URL` and it is the Neon `-pooler` URL, the advisory lock and `BEGIN`/DDL run through PgBouncer transaction pooling, which D4 says is unsafe. State that the fallback must be a direct/session-capable URL (or require `DIRECT_DATABASE_URL` when `DB_SCHEMA_BOOTSTRAP_ENABLED=true`).
- **F13 (INFO) — AC-12 empty-string case.** The testing strategy says "empty/invalid forms", but AC-12 lists four invalid values (`maybe`, `yes`, `59999`, `86400001`) and not `''`. Add an empty-string case for each of the three variables (or state that undefined is the only default path).
- **F14 (INFO) — task sizing.** T3 and T5 each carry a new module + unit suite + real-Postgres suite, and T7 rewires `server.ts` with a module-mocked suite; if the builder session has a size cap, split by module/suite and record the split in the build log. No gate impact.
