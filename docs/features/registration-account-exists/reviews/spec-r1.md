# Spec Review — r1

## Summary

❌ **changes requested** — The diagnosis is sound and independently confirmed on the Neon **development** branch: the two rows match the spec's U1/U2 (ids, usernames, `verified = false`, timestamps), there are **0 sessions**, **0 economy rows**, **2 verification tokens**, both stored emails are lowercase, and the **production** branch has no `users` table. The Render changelog (2025-09-16, live 2025-09-26) confirms the free-tier block on outbound **25/465/587**, and Brevo documents **2525**; the six stated supersessions are justified and explicit.

The plan is acyclic, fully sequential, has disjoint `files_owned`, coverage on every behaviour task, and a user-owned T9. It is nevertheless **not ready to build**: **1 BLOCKER** (AC-4's route-level `resumed` body has no owning task) and **7 MAJOR** findings (T1's impossible CI fixture check, resend failed-send token invalidation, incomplete documentation/branch-history/PII verification, merge ordering, and a malformed-port guard gap) remain. The primary ask is covered for a new/recoverable account; the exact desired pair stays owner-only (Q-1), which is an explicit non-goal and acceptable.
