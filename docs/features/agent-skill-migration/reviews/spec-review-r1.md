# Spec Review — r1

## Summary
❌ changes requested — 4 MAJOR, 9 MINOR, 3 INFO. The audit in `spec.md` is accurate: the six pipeline skills are deleted from the worktree (18 tracked files, content intact at `HEAD`), `.agents/skills/` holds 31 packs (13 tracked, 18 untracked) and `skills-lock.json` is modified-but-uncommitted, the four agent allow-lists name the deleted skills, `AGENTS.md:31` omits `.agents/`, `docs/architecture/documentation.md:3` cites the missing playbook, and `docs/features/README.md` omits exactly the three claimed features. The two-location split is confirmed by the OpenCode skills documentation (`.agents/skills` is a project compatibility source; `.opencode/skills` is registered later and takes precedence), and the T1→T2→T3→T4→T5 sequence is safe for the untracked packs (T2 tracks them before any doc/config edit, and the plan bans `git clean` and worktree-wide restores).

The blocking problems are: (1) T4 is assigned to the orchestrator, which has no shell permission and cannot run T4's verify commands or commit; (2) the allow-list check ignores `effect` and rule order, so it can pass while the permission set is wrong; (3) AC-4's 31-pack inventory/disposition has no mechanical check; and (4) the feature's own artifacts (`spec.md`, `plan.md`, `reviews/*`) and the acceptance-time status/README edits are not owned or committed by any task. The remaining findings are reproducibility and consistency gaps. No finding requires losing the untracked packs or leaving stale `.opencode/skills` references; those two critical constraints are handled by T1/T2 and AC-9.
