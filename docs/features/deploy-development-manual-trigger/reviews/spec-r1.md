# Spec Review — r1

## Summary

The spec is well-scoped and largely testable: it adds exactly the two `workflow_dispatch.environment` input lines, keeps `default: production`, preserves the automatic `workflow_run` path, and reuses the environment-scoped deploy job. The input→environment mapping, concurrency, CI-success preflight, SMTP guard split, no-live-deploy rule and Q-1/Q-2/Q-3 classification are correct, and the proposed parse/actionlint checks can run without deploying anything.

Two MAJOR findings block approval: the durable CI parse asserts the automatic path with `.includes()` substrings instead of exact values, so a realistic job-condition/ref edit can silently change the automatic path; and the documentation contract leaves concrete stale/incomplete statements in `deployment.md` and `vercel-render-neon.md` that AC-8(d) claims cannot remain. The remaining findings are MINOR/INFO.

## Notes / backlog (non-blocking)

- **F10 — INFO — Q-1 default decision.** Keeping `default: production` is consistent with the brief's "preserve production manual behavior" and is fail-closed at the placeholder guard today. It is a defensible user-owned choice; the spec correctly does not silently change it. Residual risk: after production is provisioned, accepting the default would target production, so the owner should confirm Q-1 (and consider `default: development`) before provisioning. No action required for this feature.
- **F11 — INFO — Q-3 non-main dispatch.** The spec correctly classifies the non-`main` dispatch hazard as user-owned and documents `--ref main` rather than adding a guard that would change the accepted production path. The production runbook's missing `--ref main` rule is F9; no code change is required.
- **Robustness note — INFO — diff base.** The `git diff -U0 origin/main -- .github/workflows/deploy.yml` check is two-dot; if `main` advances or the feature branch is not cut from current `origin/main`, the 4-line count can include unrelated or missing changes. Prefer the feature merge-base or `origin/main...HEAD` for the count.
- **Positive evidence verified by this review.** The exact `node -e` parse was run against a temporary copy of `deploy.yml` with only the two input-line changes: it printed `deploy.yml: workflow_dispatch offers development and production; environment mapping and automatic path unchanged` and exited 0; against the current file it failed on the options assertion, as intended. Pinned `rhysd/actionlint:1.7.12` exited 0 over a temporary `ci.yml` containing the new step (and the simulated `deploy.yml`) and over the existing `deploy.yml`/`ci.yml`. The documentation grep phrases are satisfiable by the T2 instructed text; no live deploy or provider call was made.
